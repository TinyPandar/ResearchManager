# Research Workflow

## 1. 想法与讨论

用户可以只给一个不完整想法。主 Agent先理解目标、约束和成功标准，每轮只提出少量关键问题。需要事实时优先做只读调查。

## 2. Draft Plan

信息足够后，主 Agent给出可确认的 Draft Plan，至少包含：

- 目标与非目标；
- 数据、输入输出和坐标合同；
- 架构或方法选择；
- 验证与对照实验；
- 风险、资源和停止条件；
- 角色交接顺序。

Draft Plan 未确认前，不进入完整实现。

## 3. 数据交付

需要新数据时，data_manager 先生成真实小样供确认，再创建新数据版本并运行全量验证。输出必须是不可变路径，旧版本保留。

## 4. 实现验收

implementation_manager 按确认的合同实现，完成单元、集成和必要的真实尺寸 smoke test。任何会改变研究结论的临时绕过都必须返回主 Agent重新确认。

## 5. 正式实验

experiment_manager 核对代码、配置、数据和资源后启动独立 run。每次 run 固化提交 SHA、配置、数据版本、随机种子、命令、平台任务 ID 和输出路径。

## 6. 结果与迭代

主 Agent区分“观察”“推断”和“结论”，对照基线后汇报。失败结果保留并标记原因；新假设进入下一轮讨论和 Draft Plan。

## 完成定义

一项工作只有在产物可定位、接口可解释、验证可复现、限制已说明且记录已更新时才算完成。
